# Health Warning Banners

These banners show on the event status panel and in the OBS plugin dock (they're the same checks, shown in both places):

| Banner | Exact condition | What to try |
|---|---|---|
| Incoming video codec is *{codec}*, but YouTube's ingest requires H.264, AV1, HEVC, or VP9 | Your source isn't one of those four video codecs | Switch your encoder to one of the listed codecs, or ask your system admin to enable Restream Re-encode for your event |
| Incoming audio codec is *{codec}*, but YouTube's ingest requires AAC | Your source audio isn't AAC | Switch your encoder's audio codec to AAC, or ask your system admin to enable Restream Re-encode |
| Incoming stream's keyframe interval is *{interval}*, but YouTube requires ≤4s (2s recommended) | Your keyframe interval is over 4 seconds | In OBS, go to Settings > Output and set your keyframe interval to 2 seconds (the plugin does this for you automatically — see [[Event-Streaming-Management/Operators/4. OBS Plugin Guide#Recommended OBS Output Settings|OBS Plugin Guide]]); once fixed, use the banner's **Re-check** action to confirm |
| YouTube reports: *{YouTube's own message}* | YouTube itself is flagging an ingest configuration problem | Read the message as shown — it's passed through from YouTube directly — and check the same event in your channel's Live Control Room |

These checks only run for events that restream; if your event only records/clips (no restream), you won't see them.

# My Stream Never Shows Online

The status panel can only show a generic **Offline** for "not receiving your stream" — it can't currently tell you *why* a stream was rejected. Work through this checklist in order:

1. Confirm the event is **configured** with a stream key, and that right now falls within the event's scheduled start/end window — a stream key is only accepted while its event is active. See [[Event-Streaming-Management/Operators/2. Managing Events|Managing Events]].
2. Confirm OBS (or the plugin) is using the correct, currently-active stream key for this event — a key that's been disabled or doesn't match won't be accepted.
3. Confirm there's actually a network path from your encoder to the platform (this is the same RTMP connectivity your [[FTC/FTC-AV/index|FTC A/V Setup Guide]] or [[FRC/FRC-AV/index|FRC A/V Home]] setup already depends on).
4. If none of that explains it, contact your system admin — the specific rejection reason (bad key, no active event, or a server-side issue) is recorded in server logs that only a system admin can see; see [[Event-Streaming-Management/System-Administration/6. Monitoring and Troubleshooting|Monitoring and Troubleshooting]].

# My Event Is Missing

A handful of events (particularly off-season FRC events) aren't shown to every organization automatically — an admin has to make them visible for your organization first, and a system-wide setting can hide off-season events entirely. If an event you expect isn't showing up, ask your Client Admin to check [[Event-Streaming-Management/Client-Administration/6. Event Configuration Reference#Off-Season FRC Events|Event Configuration Reference]] before assuming something's broken.

# No Matches Are Showing Up

If your event is live but no matches ever appear, the dashboard won't show you a warning for this today — it's a background sync issue between the platform and the *FIRST* Events APIs that only shows up in server logs. Before contacting support, ask your Client Admin to double-check that the event's code and season in its configuration exactly match what's published on the *FIRST* Events website, and that its timezone looks right (see [[Event-Streaming-Management/Client-Administration/6. Event Configuration Reference|Event Configuration Reference]]). If that all looks correct and matches still aren't appearing, contact support — this needs a system admin to check the sync directly.

# Clips Are Missing or Look Wrong

If a clip's recorded length comes out much shorter than expected, the platform deletes it and marks that match **missed** automatically rather than publishing a broken clip — check the Clips page for a run of missed matches around the time something went wrong with your stream. A clip that runs a bit long usually just means slightly more pre/post-match footage than intended; it still publishes normally. Clip start/end padding around each match is a system-wide setting your system admin controls — see [[Event-Streaming-Management/System-Administration/4. System Settings Reference|System Settings Reference]].

# My Upload Is Stuck

See [[Event-Streaming-Management/Operators/5. Clips, Uploads and Signage#Uploads|Clips, Uploads and Signage]] for what each upload badge means. In short: **Quota wait** clears itself; **Deferred** and **Paused** both need a system admin; **Failed** just needs a **Requeue** click from a Client Admin or User.

# YouTube Channel Needs Re-Linking

If a linked YouTube channel's row shows **"Auth failed — re-link required"** in red, its authorization has stopped renewing itself — uploads and restreams using that channel will fail until it's fixed. A Client Admin needs to click **Re-link** on the [[Event-Streaming-Management/Client-Administration/3. YouTube and Slack Integrations|YouTube and Slack Integrations]] page and sign in again to re-authorize it.

# Blue Alliance Posting Failed

For FRC events, match results and video links are posted back to The Blue Alliance automatically. If a match's Blue Alliance status shows as failed, it's usually missing or incorrect Blue Alliance credentials on the event — see [[Event-Streaming-Management/Client-Administration/6. Event Configuration Reference|Event Configuration Reference]] for where those are entered. (FTC events don't use The Blue Alliance at all, so a "skipped" status there is expected, not an error.)

# YouTube Restream or Broadcast Won't Cooperate

See [[Event-Streaming-Management/Operators/3. Running a Live Event#Going Live and Stopping the Broadcast|Running a Live Event]] for the full set of push/broadcast status text. A few specific cases:

- **Stuck on "Holding — waiting for source"** — the push is running but the platform isn't receiving your incoming stream yet; fix your incoming stream first (see [[#My Stream Never Shows Online|above]]).
- **"Go Live" stays disabled** — it only enables once the push reads "Pushing" **and** YouTube's own ingest is healthy; give it a minute after starting the push.
- **"Push error"** — hover or check the detail text next to the status; if the platform decides your source genuinely can't be pushed (for example, an unsupported format), the push gives up rather than retrying forever, and you'll need to fix the underlying issue and click **Start Push** again.

# Sign Isn't Updating

Check the sign's sync status on the Signage page. **Drifted** means someone changed it directly in AbleSign — click **Re-apply** to hand control back to the platform. **Error** shows the underlying failure message; if it's unclear, pass it to your system admin. See [[Event-Streaming-Management/Operators/5. Clips, Uploads and Signage#Signage|Clips, Uploads and Signage]].

# OBS Plugin Won't Pair or Shows No Events

- **Pairing code expired** — codes expire after a while; just click **Pair with CHS Streaming** again for a new one.
- **Device was revoked** — a revoked device can't be silently reactivated; pair it again from scratch.
- **Dock shows no events** — the dock only lists non-archived events scheduled on the specific stream key your device is paired to. Confirm today's event exists, is configured with that same stream key, and hasn't already ended or been archived.
