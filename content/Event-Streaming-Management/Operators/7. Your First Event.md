# Before You Run Your First Event

This page is a checklist that ties together the rest of the Operators section. It assumes you already have a login and, if you're using it, an installed and paired OBS plugin — if not, start with [[Event-Streaming-Management/Operators/1. Getting Started|Getting Started]].

> [!note] Testing Your Pipeline Before Game Day
> Operators can't create a rehearsal event themselves — that's a system-admin-only tool. Two things
> you *can* do ahead of time:
> - Ask your system admin whether a test event already exists on your assigned stream key, or ask
>   them to create one — a test event runs synthetic matches through the real pipeline (recording,
>   clipping, upload) so you can confirm everything works end-to-end before a real event.
> - Ask your system admin for the **OBS Test Clock** URL and add it as an OBS Browser Source. It
>   needs no login and shows a running clock (optionally with color bars and test tones) so you can
>   confirm your video and audio pipeline look right before you're on the air. If your system admin
>   changes its settings, use OBS's "Refresh cache of current page" on that source to pick up the
>   change.

# Day Before

1. Confirm your event is **configured** (not just discovered) with the right stream key, timezone, and — for FRC — Blue Alliance credentials. See [[Event-Streaming-Management/Operators/2. Managing Events|Managing Events]].
2. Confirm your OBS plugin is paired to the right stream key, or that you have the manual server/stream-key values ready if you're not using the plugin. See [[Event-Streaming-Management/Operators/4. OBS Plugin Guide|OBS Plugin Guide]].
3. If your event restreams to YouTube, confirm the channel it broadcasts to is linked and not showing "Auth failed — re-link required" (see [[Event-Streaming-Management/Operators/6. Troubleshooting#YouTube Channel Needs Re-Linking|Troubleshooting]]).
4. If you're using signage, confirm the signs you expect are assigned and not sitting in a **Drifted** or **Error** state. See [[Event-Streaming-Management/Operators/5. Clips, Uploads and Signage#Signage|Clips, Uploads and Signage]].
5. Run through the test procedure above if you haven't already this season.

# Morning Of

1. Arrive with enough time to get your A/V setup running per your program's guide ([[FTC/FTC-AV/index|FTC A/V Setup Guide]] or [[FRC/FRC-AV/index|FRC A/V Home]]) before matches start.
2. Open OBS. If you're using the plugin, confirm it shows **Paired!** and pick today's event from the dock. If not, double check your manual stream key/server settings are still correct.
3. Open the event's control center in the web dashboard and confirm its status panel looks right — no unexpected health warnings yet.
4. In OBS, click **Start Streaming**. Wait until the dashboard's **Incoming Stream** status turns **Online** (the OBS dock shows the same) before moving on — that's the platform actually receiving your feed.
5. If your event restreams to YouTube, click **Start Push** and wait for the status to read **Pushing** (with YouTube ingest healthy). Don't click **Go Live** yet.
6. Click **Go Live** only when you're actually ready for viewers to see the broadcast — for example, opening ceremonies or the first match. Until then the push runs privately. See [[Event-Streaming-Management/Operators/3. Running a Live Event#Going Live and Stopping the Broadcast|Running a Live Event]] for what each step does.

At the end of the day this runs in reverse — **Stop Broadcast**, then **Stop Push**, then stop streaming in OBS. See [[#After the Event]].

# During the Event

1. Keep an eye on the status panel (or the OBS dock) for health warning banners, and act on them using [[Event-Streaming-Management/Operators/6. Troubleshooting|Troubleshooting]].
2. Let clipping and uploading happen automatically — there's nothing to click per match.
3. If your dashboard ever shows a match as live when your stream has actually stopped, don't just keep going — see [[Event-Streaming-Management/Operators/3. Running a Live Event#If a Session Gets Stuck|If a Session Gets Stuck]].

# After the Event

1. Spot-check the Clips page for missing or missed matches, and the Uploads page for anything stuck in **Failed**, **Deferred**, or **Paused**. See [[Event-Streaming-Management/Operators/5. Clips, Uploads and Signage|Clips, Uploads and Signage]].
2. If you used signage, confirm signs you no longer need have been returned to a sensible display (or disable signage for the event from its control center).
3. If your event restreamed, confirm you stopped both the broadcast and the push (see [[Event-Streaming-Management/Operators/3. Running a Live Event#Going Live and Stopping the Broadcast|Running a Live Event]]) — an idle push left running doesn't hurt anything, but there's no reason to leave it up.
4. Note anything unusual for your Client Admin or system admin so it isn't a surprise at the next event.
