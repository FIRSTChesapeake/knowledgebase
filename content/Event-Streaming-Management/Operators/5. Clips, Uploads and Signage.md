# Clips Are Automatic

Cutting and publishing clips is a pipeline that runs on its own as matches are detected during the event — there's no button an operator clicks to "publish" a match. Your job here is reviewing what came out the other end, not approving each clip before it goes out.

# Reviewing Clips

The Clips page lists clips across your events, with each clip's status and a link through to the uploaded YouTube video. Use it after an event to spot-check that every match got a clip and uploaded correctly. If a match's video ends up much shorter than expected, the platform deletes that clip automatically and marks the match **missed** rather than publishing a broken clip — if you see matches missing this way, ask your system admin to check the recording for that time window. A clip that comes out noticeably longer than expected still publishes normally; there isn't a separate on-screen flag for that case, so a quick spot-check after the event is the way to catch it.

# Uploads

The Uploads page lists every clip's YouTube upload with a status badge:

| Badge | Meaning |
|---|---|
| YT: Queued | Waiting to upload |
| YT: Uploading | Upload in progress |
| YT: Uploaded | Done |
| YT: Failed | The upload failed after retries — a **Requeue** button appears on failed rows (Client Admin/User only) to try again |
| YT: Deferred | The platform's current operation mode is holding uploads back — a system admin needs to change the mode, or explicitly force it through |
| YT: Quota wait | The shared daily YouTube upload quota is temporarily used up — this clears on its own once the daily quota resets, no action needed |
| YT: Paused | A system admin has paused **all** uploads platform-wide — this is not something tied to your event, and only a system admin can resume it |

The status filter dropdown lets you narrow the list to most of these (All statuses / Queued / Uploading / Uploaded / Failed / Deferred / Quota wait); note that a paused upload still shows its "YT: Paused" badge in the table even though there's no separate filter option for it.

See [[Event-Streaming-Management/Operators/6. Troubleshooting#My Upload Is Stuck|Troubleshooting]] if uploads stay stuck longer than you'd expect.

# Signage

If your event has signs assigned, manage them from the Signage page. Available display types are: five named presets — **Official Pit Display**, **Nexus — Pit**, **Nexus — Queueing**, **Nexus — Audience**, and **Nexus — Test Area Wait Times** — plus **Livestream** and a free-form **Custom URL**. (Exactly which presets are usable depends on whether your Client Admin has configured a URL for your program; an unconfigured preset shows as disabled in the dropdown.)

Each sign is tied to one stream key at a time. The first time a sign is assigned to a stream key, a confirmation dialog appears: *"Take control of this sign? This sign's current AbleSign playlist will be replaced with a single item this platform controls. AbleSign's media library is untouched, but releasing control later will not restore the sign's previous playlist — it will show this platform's idle page instead."* — confirm with **Take Control**. Assigning (or reassigning) a sign to a stream key requires a Client Admin; once it's assigned, any Client User or Admin can switch which display mode it's showing.

Each sign shows a sync status: **Idle**, **Applying…**, **Applied**, **Drifted**, or **Error**. **Drifted** means someone changed the sign's playlist directly in AbleSign — the platform deliberately won't overwrite it automatically, so click **Re-apply** (which only appears in this state) once you're ready to hand control back to the platform. **Error** shows the raw error message underneath the badge; if it doesn't make sense, pass it along to your system admin.

Turning an event's signage on or off entirely (as opposed to picking what it shows) is done from that event's control center — see [[Event-Streaming-Management/Operators/3. Running a Live Event#Signage Controls|Running a Live Event]].
