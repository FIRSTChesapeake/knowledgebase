Open an event and go to its control center to monitor and operate it during the event itself.

# The Event Status Panel

The status panel shows three things at a glance:

- **Incoming Stream** — whether the platform is currently receiving your OBS/RTMP stream.
- **YouTube Restream** — combined health of the outgoing push and YouTube's own ingest, if this
  event restreams (see [[Event-Streaming-Management/Operators/2. Managing Events|Managing Events]]).
- **Signage** — status of any signs assigned to this event.

# Going Live vs Starting the Push

If your event restreams to YouTube, these are two separate controls, and order matters:

1. **Start Push** — begins sending your incoming stream onward toward YouTube. Do this first.
2. **Go Live** — publishes the YouTube broadcast to viewers. This only works once the push is
   active.

Stopping works in the same order in reverse: stop the broadcast before stopping the push.

# Live Preview and Pipeline Progress

The control center includes a live preview of the incoming stream, and a pipeline section showing
each match's progress through recording, clipping, and uploading. Clip creation and YouTube
publishing happen automatically as matches are detected — there's no manual "publish" step during
the event; see [[Event-Streaming-Management/Operators/5. Clips, Uploads and Signage|Clips, Uploads and Signage]] for what to check afterward.

# Health Warnings

Warning banners appear on the status panel when something needs attention — for example, an
incompatible video or audio codec, a keyframe interval that's too long for reliable clipping, or an
issue YouTube itself reports about the incoming stream. See
[[Event-Streaming-Management/Operators/6. Troubleshooting|Troubleshooting]] for what each of these
usually means.

# If a Session Gets Stuck

If a stream session appears stuck (for example, after a network drop that didn't clean up on its
own), the event control center has a force-close action for the stuck session. Use it to let the
platform start fresh the next time your stream connects; it doesn't delete anything already
recorded or clipped.
