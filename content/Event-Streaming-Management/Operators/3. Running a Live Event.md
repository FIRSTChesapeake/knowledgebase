Open a configured event to reach its control center — the page you'll use to monitor and operate it during the event itself. Everything below applies whether you're using the OBS plugin's dock or the web dashboard; the plugin dock is a live mirror of this same page (see [[Event-Streaming-Management/Operators/4. OBS Plugin Guide|OBS Plugin Guide]]).

Every control described below except signage toggles and the "if stuck" action requires **user** role or above — **readonly** members can watch this page but can't click anything on it.

# The Event Status Panel

Three status rows, each with a colored dot:

- **Incoming Stream** — gray "Offline" until the platform is actively receiving your OBS/RTMP stream; then "Online" plus resolution, bitrate, and codec.
- **YouTube Restream** — only relevant if this event restreams; see [[#Going Live and Stopping the Broadcast|below]] for the full set of states.
- **Signage** — "Unavailable" (no stream key), "Not controlling", "Controlling signage", or "Controlled by \"{another event}\"" if a sign this event would use is currently driven by a different event.

# Starting and Stopping the Push

If your event restreams to YouTube, sending your incoming stream onward is a separate step from publishing it to viewers, and the two buttons only appear if `restream_mode` isn't "none" for this event:

- **Start Push** — begins pushing your incoming stream toward YouTube. No confirmation prompt.
- **Stop Push** — appears while a push is active. Confirms first: *"Stop pushing to YouTube? This ends the RTMP feed to YouTube immediately -- restart it manually when ready to resume."*

While pushing, the **YouTube Restream** row cycles through: **Idle** (not pushing), **Starting push…**, **Holding — waiting for source** (push is up but nothing is arriving from your stream yet), **Pushing**, **Pushing — waiting for YouTube** (push is active but YouTube hasn't confirmed ingest yet, YouTube-broadcast mode only), **Pushing — ingest {health}** (YouTube has confirmed ingest but is reporting a health issue), **Stopping push…**, or **Push error** with a short detail message.

# Going Live and Stopping the Broadcast

If this event broadcasts to YouTube (rather than just pushing to a manual restream key), two more buttons appear once a broadcast exists for it:

- **Go Live** — publishes the broadcast to viewers. Disabled (tooltip: *"Start Push and wait for it to go active first"*) until the push is active **and** YouTube's own ingest is reporting healthy. No confirmation prompt.
- **Stop Broadcast** — appears once the broadcast is live. Confirms first: *"Stop this broadcast? This is irreversible on YouTube — the broadcast cannot be resumed."* Use this deliberately — there's no way to resume the same broadcast afterward.

In short: start streaming in OBS and confirm the **Incoming Stream** row reads **Online**, then
**Start Push** and wait for the **YouTube Restream** row to read **Pushing**, then **Go Live**. To
end the stream, reverse it — **Stop Broadcast** first, then **Stop Push**, then stop streaming in
OBS.

# Signage Controls

If the event has a stream key and at least one sign assigned to it, **Enable Signage** / **Disable Signage** buttons appear. You can use these if you're a Client Admin or Client User on the event's own scheduled date, or at any time if you're a system admin — Client Readonly members and non-admins acting outside the event's date range can't use these controls. Disabling confirms first: *"Disable signage control for this event? Signs on its stream key will return to the idle page."* See [[Event-Streaming-Management/Operators/5. Clips, Uploads and Signage#Signage|Clips, Uploads and Signage]] for assigning signs and switching what they display.

# Live Preview and Pipeline Progress

If enabled for your organization, the control center includes a live preview of the incoming stream, plus a pipeline section showing each match's progress through recording, clipping, and uploading. Clip creation and YouTube publishing happen automatically as matches are detected — there's no manual "publish" step during the event. A clip held for review sits in its own **Needs Review** stage alongside pending/processing/failed, so it isn't mistaken for a pipeline error; see [[Event-Streaming-Management/Operators/5. Clips, Uploads and Signage|Clips, Uploads and Signage]] for what to check afterward and how to approve or discard it.

# Health Warnings

Warning banners appear on the status panel when something needs attention — for example, an incompatible video or audio codec, a keyframe interval that's too long for reliable clipping, or an issue YouTube itself reports about the incoming stream. See [[Event-Streaming-Management/Operators/6. Troubleshooting|Troubleshooting]] for the exact wording and thresholds behind each one.

# If a Session Gets Stuck

If the dashboard still thinks your event is live after your stream has actually stopped (for example, after a network drop that didn't clean up on its own), a Client Admin can use **Clear Stale** from the Events list (its tooltip reads "Force-close stuck live session") to reset the event's status. It confirms with: *"Force-close the stale live session for '{event name}'?"*

This only cleans up the platform's own bookkeeping — it does **not** stop an actual OBS/RTMP push or an active YouTube broadcast, and it doesn't delete anything already recorded or clipped. If your stream or broadcast is genuinely still running, stop it from OBS (and, if applicable, **Stop Broadcast** / **Stop Push** above) first.
