This page is a field-by-field reference for the Event Configuration page. For the workflow view
(when and why you'd touch each field), see
[[Event-Streaming-Management/Operators/2. Managing Events|Managing Events]]. Unless noted otherwise,
every field on this page requires the **Client Admin** role to save; a tab or field a User or
Readonly member can't save renders disabled with a short note naming who can edit it, rather than an
editable form that would fail on submit (see the note in
[[Event-Streaming-Management/Client-Administration/1. Members and Roles#What Each Role Can Actually Do|Members and Roles]]).

# Minimum Configuration to Get Started

Turning a **discovered** event into a **configured** one only requires two things, filled in from the
"Configure" popup on the Events list:

- **Event Name** (optional) — free text; if left blank, the name from the *FIRST* Events API is
  used.
- **Stream Key** (required) — a dropdown of your Client's active stream keys.

Everything else below lives on the full Event Configuration page, reachable once the event is
configured.

# Basics

For a User or Readonly member, every field on this tab is disabled and there's no Save button, with
the note "Only a client admin can edit event configuration."

- **Event Name** — free text; placeholder shows the name from the *FIRST* Events API.
- **Timezone** — an IANA timezone (e.g. `America/New_York`). This is normally set automatically from
  the event's own data; if that data doesn't specify a recognizable timezone, the platform falls
  back to a system-wide default (currently `America/New_York`) rather than guessing. **Only a system
  admin can change this field** — everyone else sees it read-only, marked "(read-only)."
- **Stream Key** — a dropdown of your Client's active stream keys. Once any clip has been recorded
  for the event, this field locks (with the note "Stream key cannot be changed after clips have been
  recorded.") — only a system admin can still change it past that point.
- **YouTube Upload Channel** — a dropdown of your Client's linked channels, or "— none (clips will
  not be uploaded) —" if you don't want clips uploaded anywhere. This is optional.
- **Apply pre-roll branding video to clips from this event** — a checkbox. It only appears at all if
  your Client has a pre-roll video on file (see
  [[Event-Streaming-Management/Client-Administration/4. Branding#Pre-Roll and Post-Roll Video (Not Here)|Branding]]); defaults to off. A note underneath reminds you that post-roll, if
  configured, is applied system-wide and isn't a per-event setting.

# Blue Alliance Credentials (FRC Only)

This tab only appears for FRC events — FTC doesn't use The Blue Alliance, and a "skipped" Blue
Alliance status on an FTC match is expected, not an error.

For a User or Readonly member, both fields on this tab are disabled and there's no Save button, with
the note "Only a client admin can edit Blue Alliance credentials."

- **Auth ID (optional)** — free text, the ID half of a **Blue Alliance Trusted API** credential
  pair for this specific event.
- **Auth Secret (optional)** — a password-style field, placeholder "TBA Trusted API auth secret." If
  a secret is already saved, it shows as dots with the note "Secret is set. Leave blank to keep the
  existing value." — leaving it blank on save does not clear it.

These credentials come from The Blue Alliance itself, scoped to your specific event, not from this
platform — if you don't already have a Trusted API auth ID/secret pair for the event, that's
something to obtain through The Blue Alliance, not something support here can generate for you.

# Livestream

- **Restream target** — a choice of three radio options: **none** (default — the event only records
  and clips, no live broadcast), **YouTube channel (system-managed broadcasts)**, or **Manual RTMP
  key**.
- If set to YouTube channel mode:
  - **Livestream channel** — a dropdown of your Client's linked YouTube channels (independent of the
    YouTube Upload Channel on the Basics tab — you can upload clips to one channel and broadcast
    live to a different one).
  - **Start time (event-local, shared across all broadcast days)** — a time-of-day value.
  - **Privacy** — `public` (default), `unlisted`, or `private`.
  - **Thumbnail (shared across all broadcast days, JPEG/PNG, under 2MB)** — an image upload used for
    the YouTube broadcast.
- If set to Manual RTMP key mode:
  - **Restream key** — a dropdown of your Client's restream keys (see
    [[Event-Streaming-Management/Client-Administration/2. Stream Keys and Restream Keys|Stream Keys and Restream Keys]]).

Saving this tab requires Client Admin, consistently on both the button state and the server side.

# Broadcast Days

Shown only when Restream target is set to YouTube channel mode. Add a date to create a broadcast
"day" — each one tracks its own YouTube broadcast lifecycle and shows a watch link once live. Per
day:

- **Replace** (or **Create**, if none exists yet) starts a new broadcast for that day. Confirmation:

  > Create a replacement broadcast for Day {n}? The current one ({status}) will be kept as history
  > but no longer shown as current.

- **Remove** deletes a day. Both buttons are disabled while that day's broadcast is currently live or
  starting — you can't replace or remove a broadcast that's on the air.

Adding a broadcast day only requires the **user** role or above (not admin-only, unlike the rest of
this tab).

# Signage

- **AbleSign API Key** — a password-style field, placeholder `ablesign.tv API key (ak_...)`, with
  **Connect**, **Replace Key**, and **Unlink** actions — admin-only. Unlink's confirmation reads
  exactly:

  > Unlink the ablesign.tv integration?
  >
  > All cached signs for this client will be removed. Signs will keep showing whatever they currently
  > show — nothing changes on AbleSign itself.

- Per sign: a **Stream Key** dropdown (which event feed the sign should reflect — Client Admin only;
  disabled for a User with the note "Only a client admin can change a sign's stream key
  assignment.") and a **Display** dropdown (a preset, or "Custom URL…"). See
  [[Event-Streaming-Management/Operators/5. Clips, Uploads and Signage#Signage|Clips, Uploads and Signage]] for the day-of-event view, including **Take Control** and **Re-apply**.

# Off-Season FRC Events

Off-season FRC events don't carry a district code the way in-season events do, so they don't
automatically show up for any Client the way district-scheduled events do. This is entirely a
**system-admin** feature — there's no Client Admin control for it at all:

- A system admin sees an "Unassigned off-season events" panel (only if off-season polling is turned
  on platform-wide) and assigns a discovered off-season event to a specific Client.
- Once assigned, the event behaves like any other configured event for that Client — it shows an
  "Off-season" badge next to its program tag, but otherwise works normally.
- A separate system-wide setting can also hide off-season events entirely, everywhere, even ones
  already assigned — if your organization runs off-season events and one isn't appearing, ask your
  system admin to check that setting before assuming the event needs reassigning. See
  [[Event-Streaming-Management/System-Administration/2. System Settings Reference|System Settings Reference]].

If you need an off-season event assigned to your Client, contact *FIRST* Chesapeake technology
support at [technology@firstchesapeake.org](mailto:technology@firstchesapeake.org).
