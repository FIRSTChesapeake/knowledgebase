(when and why you'd touch each field), see
[[Event-Streaming-Management/Operators/2. Managing Events|Managing Events]].

# Basics

- **Name** — the event's display name.
- **Timezone** — used for scheduling and display. If an event's source data doesn't specify a
  recognizable timezone, the platform falls back to a system-wide default timezone (see
  [[Event-Streaming-Management/System-Administration/4. System Settings Reference|System Settings Reference]]) rather than guessing.
- **Stream key** — which stream key's incoming video belongs to this event.
- **YouTube upload channel** — which linked channel clips upload to.
- **Pre-roll** — an optional per-event override of your Client's default pre-roll video (see
  [[Event-Streaming-Management/Client-Administration/4. Branding|Branding]]).

# Blue Alliance Credentials (FRC Only)

FRC events can be linked to The Blue Alliance so match results and video links post back
automatically. This isn't applicable to FTC events.

# Livestream

- **Restream target and mode** — whether this event also restreams as a full YouTube broadcast, in
  addition to being clipped.
- **Broadcast channel and thumbnail** — the destination and thumbnail image for the restream.
- **Broadcast days** — which day(s) of a multi-day event this configuration applies to.

# Signage

Assign event signs here to control what they display (see
[[Event-Streaming-Management/Operators/5. Clips, Uploads and Signage#Signage|Clips, Uploads and Signage]] for the day-of-event view).

# Off-Season FRC Events

Off-season FRC events don't carry a district code the way in-season events do, so visibility works
differently: an admin assigns a discovered off-season event to your Client (rather than it simply
appearing based on district), and from then on it behaves like any other configured event. A
system-wide setting can also hide off-season events entirely, everywhere, regardless of assignment
— if your organization runs off-season events and they aren't appearing, check with your system
admin whether that setting is enabled before assuming an event needs reassigning.
