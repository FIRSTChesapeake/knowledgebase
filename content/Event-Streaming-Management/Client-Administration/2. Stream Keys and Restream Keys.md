# Stream Keys vs Restream Keys

These are two different credentials with two different permission models — don't assume they work
the same way:

| | Stream Key | Restream Key |
|---|---|---|
| What it's for | Your OBS setup (directly, or through the OBS plugin) uses this to send video **into** the platform for a given event. | The destination's own RTMP key (for example, YouTube's) used when an event restreams via the "Manual RTMP key" mode. |
| Who can view it (masked) | Any Client member whose Client owns the key — the Stream Keys page is reachable by Client Admins and Users (not Readonly). | Any Client member whose Client owns the key — but only Client Admins can even reach the Restream Keys page in the dashboard. |
| Who can reveal the real value | Client Admin or User (or a system admin) | Client Admin (or a system admin) |
| Who can create/change/delete/rotate it | **System admin only** — a Client Admin cannot create, rename, enable/disable, delete, or rotate a stream key | **Client Admin** (create, delete, and rotate — see below) |

> [!warning] Treat Keys Like Passwords
> Anyone with a stream key can send video into your Client's account, and anyone with a restream
> key can push to your restream target. Only reveal or share a key with the operator or system that
> actually needs it.

# Viewing and Revealing a Stream Key

1. As a Client Admin or User, open **Stream Keys** in the dashboard (this page doesn't appear in the
   nav for a Readonly member) — useful for grabbing the key value yourself to set up OBS by hand when
   you're not using the OBS plugin.
2. Every stream key belonging to your Client is listed with its **Label**, a masked **Stream Key**
   value, **Status** (Active/Disabled), and **Created** date. The blue box at the top shows the
   **RTMP Streaming Endpoint** — the server URL every stream key uses — with a **Copy** button.
3. Click **Reveal** next to a key to see its real value, then **Copy** to copy it. Click **Hide** (in
   the same spot) to mask it again.
4. There is no **+ Add Key**, **Disable**, or **Delete** control on this page for a Client Admin or
   User — those only appear for a system admin. If you need a new stream key, an existing one
   disabled, or one deleted (for example, a retired camera position), contact *FIRST* Chesapeake
   technology support at [technology@firstchesapeake.org](mailto:technology@firstchesapeake.org) or
   your system admin. The procedure they'll follow is documented in
   [[Event-Streaming-Management/System-Administration/4. System Admins and Test Mode#Managing Stream Keys|System Admins and Test Mode]].

# Creating a Restream Key

1. As a Client Admin, open **Restream Keys** in the dashboard.
2. Click **+ Add Key**.
3. Fill in **Label** (a name for this key, for example "Main Field") and **YouTube RTMP Stream Key**
   (paste the RTMP key from your YouTube Live dashboard — it's validated as 8–128 characters of
   letters, numbers, underscores, and hyphens only; anything else, including stray whitespace, is
   rejected).
4. Click **Create Key**.
5. The new key appears in the table, masked, with **Reveal**/**Copy** controls identical to Stream
   Keys, plus **Rotate** and **Delete** buttons.

# Rotating a Restream Key

As a Client Admin (for your own Client) or a system admin, click **Rotate** on a restream key's row.
This opens a dialog titled "Rotate "{label}"" with the text: *"The old value will stop working
immediately, and any encoder or event still using it will need to be updated with the new value
below."* — followed by a **New YouTube RTMP Stream Key** field, validated the same way as on
creation. Submitting replaces the stored value; the key keeps its id, label, and every event
assignment, so you don't need to repoint anything afterward. There's no live-session clause here the
way there is for stream keys, since a restream key is a destination (YouTube) key, not something an
encoder authenticates into the platform with. The rotation is recorded in the audit log.

# Deleting a Restream Key

Click **Delete** on the key's row. The confirmation reads exactly:

> Delete restream key "{label}"?
>
> If this key is assigned to any events, it will be unassigned. This cannot be undone.

If any events still reference the key, deleting it clears their restream key assignment rather than
failing — those events silently stop restreaming (their stream key and clipping are unaffected).
Double-check which events use a key before deleting it, especially close to or during a live event.
