# Secrets

Set these in your `.env` file before running the bootstrap script (see
[[Event-Streaming-Management/System-Administration/2. Installing the Platform|Installing the Platform]]):

| Secret | Purpose |
|---|---|
| `DATABASE_URL`, `POSTGRES_PASSWORD` | Primary database connection |
| `REDIS_URL` | Job queue |
| `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` | Google/YouTube OAuth |
| `TOKEN_ENCRYPTION_KEY` | Encrypts stored OAuth tokens and restream keys at rest |
| `SESSION_SECRET` | Web session signing |
| `FRC_API_USERNAME`, `FRC_API_TOKEN` | *FIRST* Events API (FRC) |
| `FTC_API_USERNAME`, `FTC_API_TOKEN` | *FIRST* Events API (FTC) |
| `SLACK_CLIENT_ID`, `SLACK_CLIENT_SECRET` | Slack OAuth |
| `DO_TOKEN` | DigitalOcean API token (used by Terraform and `doctl`) |
| `SPACES_ACCESS_KEY`, `SPACES_SECRET_KEY` | DigitalOcean Spaces (recording/clip object storage) |
| `GHCR_TOKEN` (or `GITHUB_APP_ID` / `GITHUB_APP_INSTALLATION_ID` plus a `.pem` key file) | Pushing/pulling images from GitHub Container Registry |
| `GITHUB_TOKEN` | Fetching OBS plugin releases, if that repository is private |
| `KUBECONFIG_DO`, `GITHUB_APP_ID`, `GITHUB_APP_INSTALLATION_ID`, `GITHUB_APP_PEM` | CI/CD only — configured as GitHub Actions repository secrets, not in `.env` |

# Kubernetes Secret Objects

The bootstrap script creates these as actual Kubernetes `Secret` objects, from the values above:

- `frc-clips-secrets` — the bulk of application secrets (database, OAuth, Spaces, etc.), mounted
  broadly across services that need them.
- `frc-clips-github-token` — split out on its own and mounted **only into api-server**, so a
  compromise of any other service can't leak it.
- `ghcr-pull-secret` — image pull credentials for GHCR, so the cluster can pull your built images.

# Non-Secret Configuration

Non-secret values — your domain, GHCR owner, Spaces endpoint — are supplied via `.env` and rendered
into the Kubernetes manifests at bootstrap time (see
[[Event-Streaming-Management/System-Administration/2. Installing the Platform|Installing the Platform]]). The shipped manifests use placeholder values for these until rendered:

| Placeholder in the manifests | Replaced with | Where |
|---|---|---|
| `clips.example.com` | Your `APP_DOMAIN` | ConfigMap, Ingress |
| `admin@example.com` | Your `ADMIN_EMAIL` | cert-manager's ClusterIssuer (the Let's Encrypt account email) |
| `https://nyc3.digitaloceanspaces.com` | Your region's real Spaces endpoint | ConfigMap |
| `GHCR_OWNER` (literal token) | Your GHCR owner, lowercased | Each service's Deployment manifest |

Some values ship with working defaults you can leave as-is: `DO_REGION` defaults to `nyc3`, and
`SPACES_BUCKET` defaults to `frc-clips`.

# External Dependencies

The platform integrates with:

- Google OAuth and the YouTube Data / Live Streaming APIs
- The *FIRST* Events APIs (FRC and FTC)
- The Blue Alliance Trusted API (FRC only)
- Slack OAuth
- A digital signage API (per-Client key, for event signage)
- Your Kubernetes provider (managed cluster, block/object storage)
- Your container registry (GHCR)

Each of these needs its own account/credentials set up independently before the corresponding
secret above can be filled in.
