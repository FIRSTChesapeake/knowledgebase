# Required Secrets

The platform expects the following secrets to be provided at deploy time (names only — values are
generated or obtained per-installation):

| Secret | Purpose |
|---|---|
| `DATABASE_URL`, `POSTGRES_PASSWORD` | Primary database connection |
| `REDIS_URL` | Job queue |
| `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` | Google/YouTube OAuth |
| `FRC_API_USERNAME`, `FRC_API_TOKEN` | *FIRST* Events API (FRC) |
| `FTC_API_USERNAME`, `FTC_API_TOKEN` | *FIRST* Events API (FTC) |
| `SLACK_CLIENT_ID`, `SLACK_CLIENT_SECRET` | Slack OAuth |
| `TOKEN_ENCRYPTION_KEY` | Encrypts stored OAuth tokens |
| `SESSION_SECRET` | Web session signing |
| `S3_BUCKET`, `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY` | Object storage for recordings/clips |

A separate optional secret holds a token for pulling the OBS plugin release if its repository is
private, and another holds your container registry's pull credentials.

# Non-Secret Configuration

Non-secret settings (your domain, region, and similar) are supplied via config, using placeholder
values like `clips.example.com` in the shipped manifests as a stand-in for your own domain.

# External Dependencies

The platform integrates with:

- Google OAuth and the YouTube Data / Live Streaming APIs
- The *FIRST* Events APIs (FRC and FTC)
- The Blue Alliance Trusted API (FRC only)
- Slack OAuth
- A digital signage API (per-client key, for event signage)
- Your Kubernetes provider (managed cluster, block/object storage)
- Your container registry

Each of these needs its own account/credentials set up independently before the corresponding
secret above can be filled in.
