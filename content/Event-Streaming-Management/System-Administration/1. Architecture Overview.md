# Services

The platform is a set of independently-deployed services, each doing one job:

- **api-server** — the API and auth backend the web dashboard and OBS plugin talk to.
- **rtmp-ingest** — receives incoming RTMP streams.
- **stream-auth** — authorizes incoming streams against stream keys.
- **first-poller** — polls the *FIRST* Events APIs for schedules and match results.
- **clipper** — cuts per-match clips from recordings.
- **s3-mover** — moves finished recordings/clips to object storage.
- **uploader** — uploads clips to YouTube.
- **blue-alliance** — posts FRC results/video links back to The Blue Alliance.
- **slack-notifier** — sends event notifications to Slack.
- **signage-controller** — drives event signage displays.
- **restream-pusher** — pushes the live restream toward YouTube.
- **web-frontend** — the dashboard UI.

The OBS plugin talks to api-server's device-auth endpoints; it isn't a separate deployed service.

# The Pipeline

Work moves between services through a job queue, roughly:

```
RTMP ingest → clip jobs → storage-move jobs → upload jobs → Blue Alliance / Slack notification jobs
```

Signage and restreaming run as their own separate job queues alongside this main chain, driven by
the same event configuration.

# Operation Modes

A system-wide operation mode setting — `record_only`, `lite_mode`, or `full_power` — gates how much
of the pipeline actually runs, and is shown as a banner in both the admin and client dashboards. See
[[Event-Streaming-Management/System-Administration/4. System Settings Reference|System Settings Reference]] for what each mode does.
