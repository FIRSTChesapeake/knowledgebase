# Prerequisites

You'll need a Kubernetes cluster (the platform is built and tested against a managed Kubernetes
offering), a container registry to push built images to, and DNS control over the domain you'll
serve the platform from.

# Manifests: k8s-do vs k8s-dev

The platform ships two manifest sets:

- A **production** manifest tree, meant for a managed/cloud Kubernetes cluster. Its manifests are
  rendered (placeholders substituted for your real values) before being applied.
- A **local development** manifest tree, meant for a local cluster (kind, Docker Desktop, or
  similar) for testing changes before they reach production.

# First-Time Setup

At a high level, bringing up a new instance is:

1. Fill in your own values for the required environment/secret configuration (see
   [[Event-Streaming-Management/System-Administration/3. Configuration and Secrets Reference|Configuration and Secrets Reference]]).
2. Build and push the service container images to your registry.
3. Run the provided bootstrap script to create the namespace, secrets, and apply the production
   manifests. The bootstrap process is idempotent — safe to re-run if a step fails partway through.
4. Point your domain's DNS at the cluster's ingress.

> [!warning] DOKS Control-Plane Upgrades and Admission Webhooks
> If your cluster is DigitalOcean Kubernetes (DOKS), be aware that DOKS refuses control-plane
> upgrades if any admission webhook's timeout is outside 1–29 seconds. cert-manager's default
> webhook timeout is 30 seconds and must be overridden, or a routine cluster upgrade will be
> blocked.

# Verifying the Deploy

Once applied, confirm every service comes up healthy before pointing real traffic at it — the
Monitoring page covered in
[[Event-Streaming-Management/System-Administration/6. Monitoring and Troubleshooting|Monitoring and Troubleshooting]] is the same view you'll use for day-to-day operation, so it's worth checking it
looks right immediately after install too.
