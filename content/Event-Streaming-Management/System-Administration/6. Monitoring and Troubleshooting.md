# Status Page

The admin Status page shows a live card per service (with a restart action per service), cluster
node metrics, storage/PVC usage, and a live summary of currently-running events. Start here first
when something seems off.

# Logs

The admin Logs page streams pod logs directly from the cluster, so you don't need `kubectl` access
to read what a service is doing.

# Jobs

The admin Jobs page shows queue depth for each pipeline stage described in
[[Event-Streaming-Management/System-Administration/1. Architecture Overview#The Pipeline|Architecture Overview]]. A backlog here usually means a downstream service is stuck or has been scaled down too
far. "YouTube uploads paused" here means either the system-wide quota limit or the current
operation mode — see
[[Event-Streaming-Management/System-Administration/4. System Settings Reference#YouTube|System Settings Reference]].

# Health-Check Banners

The same health-warning banners operators see (see
[[Event-Streaming-Management/Operators/6. Troubleshooting|Troubleshooting]]) are backed by explicit
checks for codec compatibility, keyframe interval, and configuration issues YouTube itself reports.
If an operator reports a warning you can't explain from that page, check the Status and Logs pages
for the specific service (rtmp-ingest or restream-pusher, depending on the warning) next.

# YouTube Channel Re-Authentication

A linked YouTube channel that fails to refresh its access token is flagged as needing
re-authentication; uploads and restreams using it will fail until an admin re-links it (see
[[Event-Streaming-Management/Client-Administration/3. YouTube and Slack Integrations#YouTube|YouTube and Slack Integrations]]). This is a per-Client action — a system admin can see that a
channel is flagged, but only that Client's admin can complete the re-link.
