The system admin **Settings** page is organized into tabs, one row per setting. Every setting here
is system-admin-only — there's no client-level equivalent for anything on this page. This is a
field-by-field reference; for the workflows that actually change these day-to-day, see
[[Event-Streaming-Management/System-Administration/7. System Admins and Test Mode|System Admins and Test Mode]] and
[[Event-Streaming-Management/System-Administration/6. Monitoring and Troubleshooting|Monitoring and Troubleshooting]].

# General

| Setting | Default | Purpose |
|---|---|---|
| Operation Mode | `record_only` | See [[Event-Streaming-Management/System-Administration/1. Architecture Overview#Operation Modes|Architecture Overview]] for exactly what each of the three modes does. Rendered as a 3-button mode card, not a dropdown. |
| Sweep Interval (hours) | `6` | Hours between automatic orphan-file sweeps of clips and raw recordings. Set to `0` to disable. A **Sweep Now** button runs one immediately without waiting for the interval. |

Switching out of `record_only` doesn't retroactively push out deferred uploads by itself. The
General tab also shows a count of currently-deferred uploads and a **Release Deferred Uploads**
action to send them all now — that action is blocked while Operation Mode is still `record_only`
(there's nothing useful to release into), so change the mode first if you want the backlog to go
out.

# Scaling

One row per background worker, each a **min / max replica count** pair. Saving a row directly
patches that worker's Kubernetes Deployment replica count — there's no real autoscaler behind this;
raising the minimum scales up immediately, lowering the maximum only clamps down if the worker is
currently above it.

| Worker | Min default | Max default |
|---|---|---|
| Clipper | 1 | 5 |
| S3 Mover | 1 | 3 |
| Uploader | 1 | 3 |
| Blue Alliance | 1 | 2 |
| Slack Notifier | 1 | 2 |
| Signage Controller | 1 | 1 |
| Restream Pusher | 1 | 1 |

If a queue is backing up and its worker is already at its max, raise the max here before assuming
something is broken — see
[[Event-Streaming-Management/System-Administration/6. Monitoring and Troubleshooting#Jobs|Monitoring and Troubleshooting]].

# Match Polling

| Setting | Default | Purpose |
|---|---|---|
| Active poll interval | 30s | How often the platform polls the *FIRST* Events API for a currently-live event. |
| Idle poll interval | 300s | How often it polls when nothing is live. |
| Wait for match scores | on | Hold an upload until the match API reports final scores (rechecked every 60s) rather than uploading before the score is official. |
| System-Wide Fallback Timezone | `America/New_York` | Used when an event's own *FIRST* Events API data doesn't specify a recognizable IANA timezone. See [[Event-Streaming-Management/Client-Administration/6. Event Configuration Reference#Basics|Event Configuration Reference]] for where this shows up on an event. |
| FRC schedule polling | off | Enable/interval (hours) for proactively polling the FRC event schedule, separate from active-event polling. |
| FRC off-season polling | off | Additional gate on top of FRC schedule polling specifically for off-season events — see [[Event-Streaming-Management/Client-Administration/6. Event Configuration Reference#Off-Season FRC Events|Event Configuration Reference]]. |
| FTC schedule polling | off | Enable/interval (hours), same idea as FRC. |
| FRC / FTC selected season | 2026 | Which competition season's events to poll — a dropdown, not a plain field, with its own **Refresh Now** button. |

# Ingest

| Setting | Default | Purpose |
|---|---|---|
| Stream preview | off | Allow non-admin Client members to view the live stream preview (otherwise preview is admin-only). |
| Stale session auto-reset | on / 120s | Automatically reset a stream-auth session that's gone stale for longer than the timeout. |
| Recording wedge auto-kick | on / 90s | Automatically kill a recording that's stopped progressing (wedged) for longer than the timeout, so a stuck stream doesn't block the ingest slot indefinitely. |
| Keyframe check | **off** / 120s | Whether stream-auth periodically probes each active stream's keyframe interval via `ffprobe`. Off by default because the probe is memory/CPU-intensive; turning it on is what enables the keyframe-interval health-check warning described in [[Event-Streaming-Management/System-Administration/6. Monitoring and Troubleshooting#Health-Check Banners|Monitoring and Troubleshooting]]. |
| Raw segment length | 60 minutes | Duration of each raw recording segment on disk. **Changing this restarts the rtmp-ingest deployment** — expect a brief interruption to any stream currently connecting. |

# Clipping

| Setting | Default | Purpose |
|---|---|---|
| Padding before / after | 30s / 60s | Extra seconds captured before/after a match's official window when cutting a clip. |
| Clipping tolerance | 10s | Minimum acceptable shortfall before a clip that came out shorter than expected is flagged rather than accepted silently. |
| Start delay | 10s | Delay before a dequeued clip job actually extracts its clip, so the raw recording segment has time to finish flushing to disk. |
| Max clip retries | 3 | How many times a failed clip extraction is retried before landing in Jobs as permanently failed. |
| Stale clip sweep | on / 15 min | A clip job stuck past this timeout is treated as failed and swept (ffmpeg itself times out at 10 minutes; 15 gives overhead). |
| Fade in / fade out | off / 14 frames each | Optional fade at clip start/end, in frames at the clip's native frame rate. |
| Clean up EFS after S3 move | on | Delete the on-disk copy once it's safely in object storage. |
| Disk full threshold | 5 GB | Minimum free space on the recordings volume before the platform blocks new streams rather than risk filling the disk mid-recording. |

Re-encoding behavior for restreamed sources (governed by the Livestream Restreaming switch under
[[#YouTube]]): when re-encoding is enabled, a non-H.264 source is transcoded to a matching
royalty-free encoder for its codec family, except HEVC sources, which are downconverted to H.264
rather than re-encoded as HEVC (to avoid H.265 encoder licensing exposure). With re-encoding
disabled, an unsupported source produces a clear error naming the codec rather than a silent
failure.

# YouTube

- **Quota Throttle** — the platform's YouTube Data API usage is a **single system-wide daily
  quota**, not a per-Client quota. `youtube_quota_throttle_enabled` (default on) turns throttling on
  at all; `youtube_daily_quota_limit` (default 10,000 units/day) is the budget itself. When the
  budget is nearly spent, uploads across every Client can show as paused — see
  [[Event-Streaming-Management/Operators/5. Clips, Uploads and Signage#Uploads|Clips, Uploads and Signage]]. Per-action costs are also settings, not hardcoded: a video upload
  costs 100 units and a playlist insert costs 50 units by default; the live-broadcast and
  live-stream costs (50 units each by default) are explicitly marked in the platform as provisional
  estimates, since YouTube doesn't publish an official figure for those two.
- **Upload privacy** — default `unlisted` (options: `public`, `unlisted`, `private`) for videos the
  platform uploads.
- **Automatic token refresh** — on by default, with a configurable refresh window (default 15
  minutes before expiry) and a fallback expiry assumption (default 3600s) for channels that don't
  report their own token lifetime.
- **Description footer** — text appended to every uploaded video's description; blank by default.
- **Max upload retries** / **deferred-check interval** — default 3 retries; deferred (mode-blocked)
  uploads are re-checked for release every 60 minutes by default.
- **Restream switches** — two independent on/off switches, each naming the path it governs:
  - **Manual-key restream** (default **on**) — the legacy path where a pasted YouTube stream key is
    forwarded directly by RTMP.
  - **Livestream Control Center restream** (default **off**) — the full YouTube-broadcast
    restreaming path. The platform's own description for this one is explicit: "Off by default —
    enable deliberately after testing."
  They are not interchangeable and don't have to be set the same way. A **re-encode** switch
  (default off) sits alongside the Control Center path — enable it only if your source's keyframe
  interval/GOP isn't copy-safe for YouTube's ingest, since re-encoding costs CPU. Turning re-encode
  on also disables the YouTube-ingest-compatibility health check entirely, since re-encoding makes
  source-codec compliance moot.

# Blue Alliance

- **Submit to Blue Alliance** — default **off**. When on, the platform submits match video links to
  The Blue Alliance's Trusted API after a successful YouTube upload — but only while Operation Mode
  is `lite_mode` or `full_power`; it never runs in `record_only` regardless of this setting (see
  [[Event-Streaming-Management/System-Administration/1. Architecture Overview#Operation Modes|Architecture Overview]]).

Per-event Blue Alliance credentials are set from
[[Event-Streaming-Management/Client-Administration/6. Event Configuration Reference#Blue Alliance Credentials (FRC Only)|Event Configuration Reference]], not here.

# OBS

- **Encoder Profile** — the output settings pushed to every paired OBS plugin the next time it
  checks in. These are the actual values applied, not just a recommendation:

  | Setting | Default |
  |---|---|
  | Resolution | 1920x1080 |
  | Frame rate | 30 fps |
  | Video bitrate | 4500 kbps (the platform's own note: YouTube recommends 3000–6000 kbps for 1080p30 live) |
  | Keyframe interval | 2s (YouTube requires ≤ 4s) |
  | Rate control | CBR (YouTube requires CBR for live streaming) |
  | Video encoder | `auto` (or force x264 / NVENC / QuickSync / AMF) |
  | Audio bitrate | 128 kbps |
  | Audio sample rate | 44100 Hz |

- **Plugin Distribution** — the GitHub repo the Download button pulls the latest release from, a
  minimum-version string (advisory only — older plugins still work but show an update banner), how
  often the plugin checks for updates (default every 6 hours), and a switch to disable the Download
  button entirely.
- **Pairing** — a platform-wide kill switch for the pairing API (**off by default**), pairing-code
  lifetime (default 15 minutes), device-token lifetime (default 365 days), and a rotation grace
  period (default 24 hours) during which an old and new device token both still work while a plugin
  picks up its refreshed token. See
  [[Event-Streaming-Management/Client-Administration/5. OBS Plugin Devices|OBS Plugin Devices]] for the client-facing side of pairing.

# Slack

Platform-wide notification toggles (admin notifications on by default, client notifications off by
default), plus the system Slack workspace connection and per-failure-type admin alert toggles (clip,
upload, storage-move, and Blue Alliance-submission failures) — all separate from a Client's own
Slack workspace connection at
[[Event-Streaming-Management/Client-Administration/3. YouTube and Slack Integrations#Connecting Slack|YouTube and Slack Integrations]].

# Test Mode

Settings that shape how test events (see
[[Event-Streaming-Management/System-Administration/7. System Admins and Test Mode#Test Events|System Admins and Test Mode]]) behave, plus the OBS Test Clock's own display options:

- **Test event timing** — match length (default 90s), dwell time between matches (default 10s),
  time between match cycles (default 8.0 minutes), and a delay before the first simulated match
  starts (default 60s).
- **Test mode upload** (default **off**) and **test mode restream** — whether a test event actually
  sends uploads/restreams out, versus just exercising the pipeline internally.
- **OBS Test Clock display** — 12/24-hour clock format (default 24-hour), display timezone (default
  UTC), whether to show color bars and diagnostic overlay (both on by default), a beep interval, a
  minute-chime toggle (on by default), an audible reference-tone toggle (off by default) with a
  channel selection (both/left/right) and volume (default 20%).
